# FileSage 实施路线

本文只列当前未完成的验收工作。产品范围以 [PRD](PRD.md) 为准，技术决策见 [TECH](TECH.md)，已有证据见 [验收范围](ACCEPTANCE.md)。

**当前状态：** 公开 MIT 仓库持续集成正常，核心 MVP 已部署到个人 Linux 服务器；尚无稳定版 Release。

## 剩余工作

| 优先级 | 工作 | 完成条件 |
| --- | --- | --- |
| P0 | 部署与数据恢复 | 在目标 Linux 主机完成整机重启、挂载恢复和服务恢复；验证只读卷、卸载卷与空间不足。v27 数据库与样本文件的隔离备份、恢复及 v28 候选升级已通过，真实数据恢复仍待验。 |
| P0 | 文件竞争与故障恢复 | Linux race 已验证同目录移动在审批后遇到同大小源内容改写且恢复原 mtime 时，计划失效、目标不发布、外部数据保留并记 stale 审计；fsroot 回归验证复制目标发布后源变化时拒绝删除来源并保留两份文件。仍需覆盖真实跨卷执行中的复制期间修改、源复核与删除之间的并发及失败清理。 |
| P1 | Agent 实例验收 | 在持久部署版本上覆盖分类、照片归档、重复清理、压缩包操作、计划终态续聊、上下文恢复及失败／恢复流程；确保计划审阅、执行模式和审计一致。 |
| P1 | 真实文件兼容性 | 用真实业务样本验证 Office、EPUB、RAW／HEIC、音视频编解码器和归档格式；对不支持的 RAR 方法保持明确失败。 |
| P1 | 依赖更新 | 审阅开放的 Dependabot PR 与失败检查；评估主要版本兼容性，并让可合并更新通过当前主线 CI。 |
| P1 | 容量与性能 | 对多卷索引、超大目录、批量上传和并发阅读建立可复现基线；按 [技术验收指标](TECH.md#已选性能与可靠性基线) 记录设备、数据集、吞吐和资源使用。 |
| 用户验收 | 移动设备 | 用户在实体手机验证导航、上传、阅读和 Agent 对话；保留浏览器窄屏自动检查作为回归。 |
| 发布门槛 | 稳定版包 | 服务器隔离环境已通过当前工作区 Release 包结构、SHA-256、字节级可复现归档、解包启动、SQLite v27→v28 迁移、无基础镜像容器首启及以 `filesage` 用户运行的 transient systemd 单元检查；仍需在干净 Linux amd64 主机验证正式 service 模板的首次安装和升级，再确定版本号与发布说明。 |

## 明确边界

- FileSage 没有登录或 HTTPS 终止，产品只面向本机或可信局域网。
- 目前没有稳定版或预编译 Release；仓库中的发布工作流尚未通过正式标签实际发布。
- 完成状态以可复核的运行证据为准，测试通过不代表所有文件格式、主机配置或真实手机均已验收。
