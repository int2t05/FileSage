# ADR-0008：Agent 单文件文本编辑候选暂存

## 状态

**已决定（实现与 Linux 端到端验证通过）。**

> 当前执行门禁由 [ADR-0009](0009-agent-tool-steps.md) 管理；本文保留候选暂存与隐私边界。下述逐项审批流程属于原决策记录，当前交互已被取代。

## 背景

Agent 需要在用户确认后读取单个文本文件，生成可审阅、可修改并经逐项审批的候选正文。旧正文和候选正文不得进入 SQLite、对话历史、审计或日志；审批与实际写入必须分离，执行仍需显式确认。

## 决策

- 首期只支持管理根目录内、无软链接、无多重硬链接的普通 UTF-8 `.txt`、`.md`、`.markdown`、`.mdown` 文件；源文件和候选均限制为 32 KiB。仅用户确认后才读取并发送源正文给模型。
- 候选正文只存于 `FILESAGE_DATA_DIR/agent-text-staging`：目录权限 `0700`、文件权限 `0600`，文件名使用随机操作 ID。SQLite 只保存 SHA-256 和大小；不保存旧正文、候选或差异。临时预览接口返回源与候选正文并设置 `Cache-Control: no-store`，普通计划与历史不返回正文。
- 用户修改候选时，服务重新校验源指纹，创建新计划版本和操作 ID，并清空旧审批。逐项批准不写文件；用户再次显式执行后，服务再次核验源指纹和暂存摘要，再调用原子版本保护写入。
- 成功、拒绝、失效和无法确定的部分结果会清理候选。重启恢复不自动执行：源仍匹配时恢复为可重新执行；已写入候选且可验证时记录成功；缺失、损坏或状态不匹配时标为需人工核查。启动恢复会清除数据库无活动计划引用的孤立候选。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| SQLite BLOB 保存候选 | 易于事务绑定和备份，但数据库备份会长期保留内容，违背不保存候选正文的约束。 |
| 每次恢复时重新调用模型生成候选 | 无需持久候选，但结果可能变化，审批无法继续绑定原候选，也会在无用户确认的新调用中再次发送正文。 |
| 私有文件暂存，数据库仅留摘要 | 候选可跨重启审阅，摘要可验证；需要限制目录权限并在终态与恢复时清理。**采用此方案。** |

## 接口与限制

`GET /api/v1/agent/plans/{planId}/operations/{operationId}/preview?expectedPlanVersion=N` 仅在计划版本及源指纹仍匹配时返回 `sourceContent` 和 `proposedContent`。专用 `PUT /api/v1/agent/plans/{planId}/operations/{operationId}/content` 接收 `expectedPlanVersion` 与修改后的 `proposedContent`，产生新方案版本；候选上限 32 KiB，请求体上限 256 KiB。对话与模型的现有通用消息／响应限制保持不变。

文本编辑使用独立模型传输边界：请求与响应各不超过 512 KiB，单条消息与模型内容各不超过 256 KiB，以容纳 JSON 转义后的 32 KiB 正文；这不会放宽文件正文与候选的 32 KiB 上限。

若进程在文件写入后、状态落库前崩溃，恢复仅在目标文件内容与候选摘要匹配时判定成功；若源仍保持原指纹，保留候选并等待新的显式执行；其他情况记录部分完成并要求人工核查。候选暂存目录损坏、不可访问或磁盘空间耗尽会阻止相关操作，不降级到数据库存正文。

## 验收

- 未确认时不读取正文；正文、候选与差异不出现在数据库、历史、普通计划或日志。
- 预览要求匹配版本与文件指纹；修改候选创建新版本并重置批准；批准不写文件，显式执行后才原子更新。
- 覆盖拒绝／批准／执行／冲突／硬链接拒绝／候选损坏／重启恢复及候选清理，并验证目录和文件权限。
- Windows Go 测试、Linux 测试二进制编译及用户 Linux 服务器集成测试均通过后，才可标记实现成熟。
