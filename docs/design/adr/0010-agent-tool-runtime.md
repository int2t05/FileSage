# ADR-0010：Agent 工具调用与每轮索引上下文

## 状态

**已采纳；本地实现，Linux 端到端验收待 CI。**

## 背景

对话只向模型描述工具目录、却不执行模型工具调用，导致 Agent 无法自主搜索文件；照片归档也因此要求用户手填可从索引发现的目录。需要让自然语言目标进入实际工具循环，同时保留文件计划审计。

## 决策

- 对话使用 OpenAI-compatible Chat Completions 流式函数调用；模型可自动选择只读索引工具并反复接收工具结果，直到澄清、回复或提交计划。
- 每轮从当前索引读取状态和根目录摘要；`get_file_index_status` 与 `search_files` 只返回路径、类型、大小、修改时间和拍摄时间，不读取文件正文。索引摘要、路径、名称及工具输出均视为不可信数据。
- `propose_plan` 将完整操作交给现有服务端校验与审批流程，不直接写文件。普通写入仍需用户审阅整份计划；已审核计划按持久化的 bypasspermission／手动模式执行。
- 工具循环最多 6 轮、8 次调用；搜索最多返回 40 项，单次工具结果不超过 24 KiB。失效或不可用的索引明确返回状态，不能把空结果当作目录为空。
- 照片归档默认搜索管理根目录，输出到 `按拍摄日期归档/YYYY/MM`；同名目标自动编号，无拍摄日期的图片跳过。模型收到的仅是索引元数据，执行前仍检查当前文件快照。
- Shell 接受任意 Bash 语法，不设命令白名单；只在 Bubblewrap 暂存副本中运行。宿主目录、网络和未列入差异的副作用不可访问；计划审核、文件快照复核、资源预算和统一写回保持不变。
- 工具过程只向前端发送简短当前动作；工具调用记录作为本轮临时上下文，不持久化为聊天消息或日志正文。

## 方案比较

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 纯提示词或 JSON 回复模拟工具 | 不产生真实调用和可验证回执，模型仍需用户重复给路径 | 不采用 |
| 模型直接改文件或运行宿主 Shell | 自主性高，但绕开计划审计、文件协调和冲突复核 | 不采用 |
| 函数调用驱动索引查询与待审计划 | 支持自主发现与连续推理，写入继续复用现有校验、审批和审计 | **采用** |

## 并发与失败

会话共享最新可用索引，但索引结果只用于发现，不构成文件当前状态证明。计划创建、用户审核和每项写入继续使用现有根目录约束、文件快照与协调器；并发修改导致冲突时刷新并重新规划，不覆盖变化后的文件。工具超限、调用失败或模型停止时明确返回，不虚构执行结果；已完成写入保留真实回执。

## 验收

- 模型请求携带索引摘要和工具定义，能够流式返回工具调用、接收真实结果并继续调用。
- “按拍摄日期归档照片”无需来源／目标路径即可查找索引、生成带明确范围和目标的待审计划；确认前不移动文件、不发送图片正文。
- 工具状态在对话中简洁可见；桌面 1440 px 和手机 390 px 下输入、会话、计划均可用。
- `go test ./...`、Web 测试、类型检查和生产构建通过；Linux Bubblewrap 端到端用例在 CI 通过后才可发布。
