# ADR-0007：React 前端与 UI 组件策略

## 状态

**已采纳。**React、TypeScript、Vite、Radix Primitives 与 Lucide 已用于当前前端。

## 决策

- 使用 React + TypeScript + Vite，作为单页浏览器前端，由 Go 服务同源提供静态资源。
- 采用 Radix Primitives 处理对话框、菜单、选择器等需要键盘与焦点管理的基础交互；业务组件和视觉样式由 FileSage 自己维护，不引入完整后台模板。
- 使用 `lucide-react` 作为唯一图标集，按需导入。
- 页面以真实目录为核心：通用文件默认列表，照片页默认网格；浅色主题首期；桌面侧栏导航，手机底部四入口（文件、照片、Agent、任务）。

## 理由

FileSage 的关键页面包含长目录、大批量操作、计划审核、步骤状态和多格式阅读，需可控的组件组合和跨浏览器交互。React 满足用户指定的框架；Radix 保留自有界面风格并提供基础键盘／焦点行为；按需导入 Lucide 图标能维持统一图形语言。Vite 与同源静态托管减少开发和部署组件。

## 代价与约束

- 文件列表、移动端操作、阅读器和长列表性能仍需实际实现与验收；框架选择本身不保证性能或无障碍质量。
- Radix 是低层交互原语，FileSage 仍需负责样式、语义标签、错误与空状态及屏幕阅读器说明。
- 任何图标和 UI 依赖在发布前仍需检查许可证、版本、构建产物和安全更新。
- 设计方向与原型见[UI/UX 基线](../UIUX.md)及 [React 原型](../prototype/)。

## 被否决的替代方案

Vue 3、Svelte 与 React 一样可行，但用户明确指定 React。整套 Ant Design、Element Plus、PrimeVue 后台模板不采用，以避免文件工作台被通用管理台模式限制；Radix + 自有产品组件可渐进实现。

## 验证

React 生产构建、前端自动测试和 320／360／390 px 浏览器视口检查已通过。视口检查不能代替实体手机的触控、软键盘和移动浏览器验证；键盘与屏幕阅读器仍需按主要流程补充检查。
