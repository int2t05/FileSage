# ADR-0009：Agent 工具步骤、计划门禁与权限模式

## 状态

**已采纳；当前工作区 Go／React 自动化测试和双轮窄屏 Chromium E2E 通过。会话摘要迁移 v28 尚未部署到持久服务；实体手机验收仍由用户完成。**

## 背景

Agent 已支持多类文件操作和隔离 Shell。原流程把计划、文件操作审批和 Shell 差异审批拆成多个确认面板，增加用户操作，也让不同工具难以共享会话、进度和审计语义。后续可能增加搜索、读取、写入和归档工具，需要保持统一入口，同时让具体文件边界仍由服务端负责。

## 决策

- Agent 用稳定的动作 ID 表示有序工具步骤。每个内置工具在服务端显式登记用途、输入契约、执行策略、输入校验和执行器；执行结果复用计划、步骤状态与审计记录。未知或未登记的动作不可执行。
- 对话先澄清并确认任务和数据范围，再生成最少必要计划。用户审计整份计划是所有写操作的共同门禁。
- 同一会话可连续处理多项任务。待审或执行中的计划锁定新输入；计划终态后，服务端将持久化步骤结果写成聊天回执，再允许继续。
- 完整对话保存在 SQLite；每轮只向模型发送最多 4 KiB 的会话摘要和最近 24 条消息（历史消息最多 60 KiB）。摘要作为普通上下文消息发送，不提升为系统指令；它只用于恢复明确目标、偏好、已确认决定、相关路径和未解决问题，不具备授权效力，也不代表文件当前状态。新计划仍须从当前索引和文件系统重新核验。
- `bypasspermission` 默认为开启。开启后审阅计划会顺序执行；关闭后计划只被审阅，每次仅执行下一步。服务端在同一事务中核对设置并保存该计划采用的模式；设置变化不能改变已审阅计划。客户端提交其展示的预期模式，设置竞态返回 `409` 且不执行。
- Shell 使用动作 ID `run_shell`，和其他工具共享会话、计划和执行模式。命令只在 Bubblewrap 隔离暂存区运行；命令、退出码和差异属于同一个计划步骤。工具调用详情默认折叠，展开后查看命令、退出码和文件变化；每个文本差异以新增／删除行呈现。原始输出只在隔离执行期间限量保存在内存中，不写入数据库或 API 响应；历史仅记录退出码和是否省略过输出。不保存完整旧文件正文。执行完成后，仅新增文件仍可从当前文件重建新增差异，修改或删除的旧行不再可恢复。
- 每个工具仍须绑定管理根目录、输入状态、冲突规则和必要资源限制。新增工具必须提供相应的快照校验、失败状态及针对性测试；共用计划流程不代表工具共用相同的文件安全实现。
- 首期只接受代码显式登记的内置工具，不加载任意插件，不让模型直接调用宿主 Shell，也不允许模型在执行期间动态追加依赖步骤。无法预先安全验证的任务继续澄清或拒绝。

## 方案比较

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 文件操作和 Shell 各自维护审批／进度流程 | 容易逐项添加功能，但用户交互、恢复和审计语义重复；Shell 还会产生大量细碎确认 | 不采用 |
| 任意动态插件或远程工具运行时加载 | 扩展灵活，但信任、权限、版本和执行来源变复杂，超出个人单机 MVP | 不采用 |
| 稳定动作 ID + 服务端静态工具登记 + 统一计划步骤 | 增加工具时仍需写专用校验和执行器；计划、权限门禁、进度和审计保持一致 | **采用** |

## 后果与边界

计划内步骤必须可预先独立预检，因此首期不支持依赖前一步未确定结果的动态工具链。`bypasspermission` 只省去每一步的确认，不能跳过整份计划审计、根目录限制、状态复核、冲突处理或审计记录。永久删除仍需要计划级明确确认。设置页和计划响应都显示模式，避免把“默认执行”误解为无门禁执行。

增加工具时，服务端至少需要登记稳定 ID、用途、输入契约、执行策略、校验器和执行器；按该工具的影响定义快照、限制和结果语义；前端提供简洁目的和状态，并在必要时增加可折叠的工具专属详情。模型提示或响应格式不得成为授权来源。

工具目录只统一计划运行时的校验与执行分发；新增能力仍须同步对话输入协议、数据使用提示、存储允许值、前端必要的确认卡及验收用例。这样可让工具共享审批与审计，同时避免把工具专属的安全边界藏进通用执行器。

## 验收

- 多会话切换和刷新可恢复当前会话；“新对话”保留已有历史。
- 计划终态后可在同一会话发送后续任务；活动计划仍不能被新消息打断，摘要和执行结果用于恢复上下文。
- 长会话只向模型发送摘要和有界的最近消息；摘要不出现在 API 响应中，不得代替审批、文件索引或当前状态复核。
- 默认 bypass 与手动模式均使用同一计划和步骤状态；设置跨重启持久化，并只影响之后审核的计划。
- 同时修改全局设置时，过期客户端模式不能启动计划；版本／文件冲突返回最新状态，不自动重发写请求。
- Shell 在隔离副本生成一次差异；整份计划审核后按所选模式提交该步骤，写入复核和审计完整，无逐文件审批。
- 至少覆盖会话恢复、模式切换、手动单步、bypass 顺序执行、停止、失败、冲突和 Shell 差异的 Go／React 自动化测试；再对窄屏布局及 Linux 服务端真实请求做端到端复验。
