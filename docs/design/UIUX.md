# FileSage UI/UX 设计基线

**设计状态：** React 页面按本基线实现；窄屏浏览器检查已通过，实体手机触控与软键盘验收仍待完成。实现与验收边界见[验收记录](../ACCEPTANCE.md)和[项目状态](../STATUS.md)。

## 设计方向

FileSage 应像一个目录优先的文件工作台：真实目录是导航和分类的核心；照片、文档、Agent 是同一批文件的不同浏览和操作入口，不另造虚拟分类体系。页面先显示当前对象、状态和可执行动作；技术细节、历史记录和补充说明按需展开，同一目的、状态或结果只出现一次。空态只保留一条能说明现状或下一步的文字。桌面端优先提供高效、信息密度适中的文件列表；移动端保持目录浏览、上传、预览和审批可用，避免依赖右键或拖拽。

采用浅色优先的中性界面、深石墨文字、单一松绿色强调色、明确的成功／警告／危险状态色。MVP 使用浅色主题，暗色主题暂不纳入。避免用彩色卡片替代文件名、路径、大小、修改时间等关键信息。常见动作常驻工具栏，低频动作置于更多菜单；危险动作在执行前显示影响范围。无文件选中时收起详情栏，为文件列表留出空间；选中后再显示详情。

## 信息架构与页面

| 入口 | 页面主要内容 | 交互重点 |
| --- | --- | --- |
| 文件 | 路径面包屑、搜索／过滤、按名称／修改时间／文件大小排序的文件列表或缩略图、按需显示的详情侧栏；窄屏可用目录抽屉 | 新建、上传、复制、移动、重命名、删除；批量选择后工具栏明确显示选择数量 |
| 照片 | 时间线／网格、日期与目录筛选、图片查看器 | 拍摄时间只用于照片视图；以文件元数据和真实路径定位；“按日期归档”进入 Agent 建议流程，不自动移动 |
| 任务 | 上传队列、预览／OCR 任务、Agent 分析与执行记录 | 显示排队、运行、暂停、失败、部分成功和完成；可查看每项结果 |
| Agent | 多会话对话、任务确认、简洁计划、当前步骤与结果 | 对话确认目标、目录／文件范围及数据使用；审阅整份计划后自动执行或逐步执行 |
| 阅读器 | 图片、音视频、PDF、Office、EPUB、压缩包及文本阅读 | 文件名和路径可见；同目录前后切换；状态变化后提示刷新，未保存编辑草稿始终保留 |
| 设置 | 根目录状态、挂载卷可用性、模型端点、工具状态、服务信息 | 不在浏览器展示密钥；不可用卷与解析器状态给出可理解说明 |

导航定稿：桌面侧栏包含文件、照片、Agent、任务和设置，并在侧栏显示文件服务状态；页面标题留在页面内容中，避免再重复一层面包屑。手机顶部保留品牌和服务状态，底部固定五个入口：文件、照片、Agent、任务和设置。Agent 可从导航或当前目录的上下文操作打开。

## 关键流程

**文件整理：**打开目录 → 搜索或筛选 → 选择项目 → 选择移动／重命名等动作 → 显示目标路径和同名处理方式 → 手动确认 → 展示逐项结果。对同名目标默认建议新名称，覆盖需明确选择；操作结果可从任务记录进入。

**上传：**选择文件／文件夹 → 检查目标目录、文件数与同名项 → 进入队列 → 查看单项／总体进度、速率及暂停状态 → 完成后打开目标目录。网络中断或刷新后从任务列表恢复；若浏览器要求重新选文件，清楚说明待续传项和匹配条件。

**Agent 文件操作：**选择或新建会话 → 用自然语言描述目标 → Agent 澄清 → 用户确认任务、文件范围与数据使用 → 展示按复杂度组织的计划 → 用户审阅并启动计划 → 默认连续执行；手动模式每次只启动当前步骤 → 展示当前步骤与结果。回复实时显示；侧栏只列会话标题和时间，支持新建与删除，不显示完成状态或独立任务列表；计划和工具步骤在对话内展示。任务终态后同一会话恢复输入并显示结果回执；待审或执行中保持锁定。待确认卡片承担结构化回执，不在聊天中重复方案；卡片以路径和实际发送的数据为主，模型信息默认折叠。过长的历史助手回复默认折叠，用户可展开原文。Bash 步骤显示命令摘要和结果；统一 Diff 显示文件名、行号及增删内容，完整命令、范围和多行输出收在“命令与结果”中。目录、二进制和已提交修改／删除的旧正文说明为何无法生成 Diff，不伪造旧内容。永久删除在计划级确认时明确标记不可恢复。计划中的工具步骤均由服务端校验，当前首期不在执行中动态追加依赖步骤。

模型需要查找路径时主动调用文件索引工具；工具调用在消息流中只显示当前动作和简短结果，命令、输出与差异按需展开。每轮注入最新索引摘要，搜索工具仅返回元数据；照片归档默认扫描管理根目录并直接提出计划。文件状态在计划创建、审阅和写入前复核，并发变化显示冲突，不静默覆盖。

**阅读与并发编辑：**文件详情打开阅读页或独立标签页，允许同时阅读多个文件。Agent 或外部工具改动正在阅读的文件时，旧内容明确标记为旧版本并提供重新加载；用户编辑中的草稿不丢弃，保存发现变化时进入“重新加载／另存为”冲突处理，不静默覆盖。

## 桌面与手机布局

```text
桌面：侧栏 224 px | 页面内容自适应 | 可选详情面板
手机：顶部品牌与服务状态 | 单列内容 | 固定底部五入口 | 底部操作抽屉
Agent 手机：单栏对话 | 横向会话切换 | 任务确认 | 步骤与当前状态 | 当前步骤执行按钮
阅读：返回与文件名 | 可横向滚动工具栏 | 内容区 | 目录折叠面板
```

手机先呈现文件名、类型、必要状态和更多操作，不显示桌面多列元数据；单击行打开，复选框进入批量选择。触控目标至少 44 × 44 px，底部安全区留白。面包屑可横向滚动，目录树以抽屉展示；详情面板改为独立页面／底部抽屉。Agent 输入框在滚动时停留在底部导航上方，保留软键盘与安全区空间。上传用系统文件选择器，拖拽仅作桌面增强。窄屏编辑器和阅读器保持文字缩放与明确返回路径。

Agent 页面使用以下界面提示原则：一屏只有一个主要任务；优先突出对话、当前工具动作和下一步；会话历史保持窄栏；计划详情和 Shell 命令按需展开；手机改为单列，输入区固定在安全区上方；检查 1440 px 桌面与 390 px 手机视口，清除重复标题、重复状态和装饰性卡片。

## 状态与可用性要求

| 场景 | 必须显示 |
| --- | --- |
| 首次进入／空目录 | 当前路径、可用操作及上传／新建入口；区分“确实为空”和“读取失败” |
| 慢盘／大目录 | 正在读取、已加载数量或分页；滚动加载时保留位置和选择 |
| 挂载卷不可用 | 卷名和路径、最后状态、重新检查入口；不得伪装为空目录 |
| 权限不足／空间不足 | 哪个操作和路径失败、原因、已完成与未完成数量 |
| 文件变化／并发冲突 | 文件状态已变化，阻止过时写入；提供刷新、重试或另存路径 |
| Agent 计划 | 用户目标、当前步骤、执行进度、结果与核查状态；路径、命令、差异按需展开 |
| 阅读器失败 | 已尝试的格式支持与失败原因；保留下载、详情和返回目录能力 |
| 无障碍操作 | 可见焦点、语义标签、键盘完成导航／对话框／选择；颜色不作为唯一状态信号 |

桌面文件列表支持方向键移动焦点、Enter 打开、Space 选择，Escape 关闭弹层；具体快捷键有界面提示且可由触屏／鼠标替代。对话框打开时焦点进入对话框，关闭后返回触发控件。图标按钮必须有中文可访问名称和提示，图标颜色不能独自表达风险或状态。加载、空目录、卷不可用、权限／空间不足、部分成功、冲突和阅读器失败状态均显示原因及下一步操作。

## 图标与组件基线

可直接查看 [图标规范与样例页](icon-study.html)：包含 26 个固定提交的 Lucide SVG、名称搜索、类别筛选和尺寸调整。Lucide 是已确定的图标库；图标页的暗色展示仅用于研究样式，不属于产品暗色主题承诺。

| 候选 | 适用证据 | 代价／待核验 | 建议 |
| --- | --- | --- | --- |
| Lucide | 线性图形风格适合文件操作密集界面；本地已保存 README、许可证和官方指南 | 使用 `lucide-react`，按需导入；升级依赖时检查图标变更 | **采用**，统一描边粗细和尺寸，不混用多套图标 |
| Tabler Icons | 图标覆盖广，官方许可页面说明图标为 MIT；本地有固定提交和许可文本 | 部分图标细节密度高；需统一尺寸与描边，不与 Lucide 混用 | 次选；若原型中文件类型图标覆盖更好再替换 |
| Phosphor | 多种视觉粗细可区分导航与强调状态，本地已有仓库 README 和许可证 | 风格层级容易造成图标表达不一致；确认具体框架包和许可后再用 | 备选，不建议首期使用多重量体系 |

图标库用于导航、动作和状态；文件类型使用一组有限且语义清楚的映射，未知类型使用通用文件图标。危险动作使用文字标签（如“永久删除”），不能只靠垃圾桶图标。

前端定为 React + TypeScript + Vite。组件策略采用少量 Radix Primitives 管理对话框、菜单和焦点／键盘行为，配合 FileSage 自有样式与业务组件；不用完整后台模板。复杂表格、审批卡、上传队列和阅读器工具条按产品语义设计。图标使用 `lucide-react` 按需导入。

设计令牌：间距按 4 px 递增；控件、卡片和主要工作区分别使用 8、12、16 px 圆角。主要操作高度 40 px，手机触控区至少 44 px；正文 14–16 px，关键辅助说明至少 12 px。强调色为松绿，危险色仅用于删除／冲突等状态。CSS 变量集中维护颜色、间距、圆角与阴影，避免页面各自定义视觉基线。

## 参考依据与边界

- **文件浏览：**参考 [Google Drive](https://support.google.com/drive/answer/2375177?hl=zh-Hans)、[Nextcloud Files](https://docs.nextcloud.com/server/stable/user_manual/en/files/access_webgui.html)和 [Dropbox Quick View](https://help.dropbox.com/view-edit/preview)的路径导航、列表／网格、就近排序、行操作和预览布局。
- **Agent：**参考 [Claude Code 计划审阅流程](https://code.claude.com/docs/en/common-workflows#plan-before-editing)和 [GitHub Copilot Agent Sessions](https://docs.github.com/en/copilot/how-tos/github-copilot-app/agent-sessions)的持久会话、计划先于执行和会话导航；FileSage 的文件根目录与人工门禁仍由自身规则决定。
- **布局与工具反馈：**参考 [Apple Layout HIG](https://developer.apple.com/design/human-interface-guidelines/layout/)的内容层级、留白和自适应布局；Agent 工具循环按 [OpenAI Function Calling](https://developers.openai.com/api/docs/guides/function-calling) 的“模型选工具—服务端执行—结果回传—继续推理”构建。
- **组件与图标：**采用 [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/accessibility)管理基础交互，以 [Lucide](https://lucide.dev/guide/)作为统一图标库。其他候选与许可证见[前端和图标参考索引](../../reference/catalog.md)。
- **产品对照：**参考范围覆盖 Nextcloud Files、File Browser、Filestash、Copyparty、Immich、PhotoPrism、PiGallery2、Paperless-ngx 和 Stirling-PDF。公开仓库仅保留结论、来源与哈希，不分发上游原文；资料清单见[参考目录](../../reference/README.md)及[官方页面来源](../../reference/official/manifest.json)。

这些来源用于比较交互模式，不代表 FileSage 对其视觉、性能、安全性或可访问性作出背书。设计通过浏览器的窄屏检查；键盘、触屏和真实手机验收仍以[验收记录](../ACCEPTANCE.md)为准。
