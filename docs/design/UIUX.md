# FileSage UI/UX 设计基线

更新：2026-10-18。状态：**设计基线已定，主要页面已实现**。用户指定 React，并授权其余设计按建议定稿。Agent 以自然语言对话为入口；分析确认、操作清单和执行结果在同一对话区呈现，逐项审核并二次确认执行，历史记录收起。输入支持 Enter 发送、Shift+Enter 换行。Agent 已接入文件整理、正文分类、重复项清理、照片归档、归档操作及 Shell 差异审批；具体能力与未验边界见 [README](../../README.md) 和[实施路线](../IMPLEMENTATION_PLAN.md)。文件、照片、Agent 和任务页在 320、360、390px 浏览器视口已检查；实体手机触控与软键盘验收由设备持有人后续完成。

## 设计方向

FileSage 应像一个目录优先的文件工作台：真实目录是导航和分类的核心；照片、文档、Agent 是同一批文件的不同浏览和操作入口，不另造虚拟分类体系。桌面端优先提供高效、信息密度适中的文件列表；移动端保持目录浏览、上传、预览和审批可用，避免依赖右键或拖拽。

采用浅色优先的中性界面、深石墨文字、单一松绿色强调色、明确的成功／警告／危险状态色。MVP 使用浅色主题，暗色主题暂不纳入。避免用彩色卡片替代文件名、路径、大小、修改时间等关键信息。常见动作常驻工具栏，低频动作置于更多菜单；危险动作在执行前显示影响范围。

## 信息架构与页面

| 入口 | 页面主要内容 | 交互重点 |
| --- | --- | --- |
| 文件 | 左侧目录树、面包屑、搜索／过滤、文件列表或缩略图、详情侧栏 | 新建、上传、复制、移动、重命名、删除；批量选择后工具栏明确显示选择数量 |
| 照片 | 时间线／网格、日期与目录筛选、图片查看器 | 以文件元数据和真实路径定位；“按日期归档”进入 Agent 建议流程，不自动移动 |
| 任务 | 上传队列、预览／OCR 任务、Agent 分析与执行记录 | 显示排队、运行、暂停、失败、部分成功和完成；可查看每项结果 |
| Agent | 对话、任务确认、分析结果和操作清单 | 先通过对话确认目标、目录／文件范围及数据使用，再分析；逐项审阅与审批 |
| 阅读器 | 图片、音视频、PDF、Office、EPUB、压缩包及文本阅读 | 文件名和路径可见；同目录前后切换；状态变化后提示刷新，未保存编辑草稿始终保留 |
| 设置 | 根目录状态、挂载卷可用性、模型端点、工具状态、服务信息 | 不在浏览器展示密钥；不可用卷与解析器状态给出可理解说明 |

导航定稿：桌面侧栏包含文件、照片、Agent、任务，设置置于侧栏底部；顶栏显示路径、搜索和上传入口。手机底部固定四个主入口：文件、照片、Agent、任务；设置放入“更多”菜单。Agent 可从导航或当前目录的上下文操作打开。

## 关键流程

**文件整理：**打开目录 → 搜索或筛选 → 选择项目 → 选择移动／重命名等动作 → 显示目标路径和同名处理方式 → 手动确认 → 展示逐项结果。对同名目标默认建议新名称，覆盖需明确选择；操作结果可从任务记录进入。

**上传：**选择文件／文件夹 → 检查目标目录、文件数与同名项 → 进入队列 → 查看单项／总体进度、速率及暂停状态 → 完成后打开目标目录。网络中断或刷新后从任务列表恢复；若浏览器要求重新选文件，清楚说明待续传项和匹配条件。

**Agent 文件操作：**用自然语言描述目标 → Agent 澄清 → 用户确认任务、文件范围与数据使用 → 展示服务和数据说明 → 在对话中呈现操作清单 → 用户逐项批准 → 检查冲突和文件状态 → 再次确认执行 → 展示成功、失败和未执行项。Shell 命令除命令、目的外还显示工作目录和具体文件影响；范围无法确定时只提供分析结果，不给出可执行批准按钮。审批页须突出不可恢复的永久删除。

**阅读与并发编辑：**文件详情打开阅读页或独立标签页，允许同时阅读多个文件。Agent 或外部工具改动正在阅读的文件时，旧内容明确标记为旧版本并提供重新加载；用户编辑中的草稿不丢弃，保存发现变化时进入“重新加载／另存为”冲突处理，不静默覆盖。

## 桌面与手机布局

```text
桌面（≥ 900 px）：侧栏 224 px | 文件区自适应 | 可选详情面板 280 px
手机（< 640 px）：顶部路径与搜索 | 单列文件行 | 固定底部四入口 | 底部操作抽屉
Agent 手机：单栏对话 | 分析确认卡 | 逐项方案卡（源 → 目标、理由、审批） | 执行二次确认
阅读：返回与文件名 | 可横向滚动工具栏 | 内容区 | 目录折叠面板
```

手机先呈现文件名、类型、必要状态和更多操作，不显示桌面多列元数据；单击行打开，复选框进入批量选择。触控目标至少 44 × 44 px，底部安全区留白。面包屑可横向滚动，目录树以抽屉展示；详情面板改为独立页面／底部抽屉。上传用系统文件选择器，拖拽仅作桌面增强。窄屏编辑器和阅读器保持文字缩放与明确返回路径。

## 状态与可用性要求

| 场景 | 必须显示 |
| --- | --- |
| 首次进入／空目录 | 当前路径、可用操作及上传／新建入口；区分“确实为空”和“读取失败” |
| 慢盘／大目录 | 正在读取、已加载数量或分页；滚动加载时保留位置和选择 |
| 挂载卷不可用 | 卷名和路径、最后状态、重新检查入口；不得伪装为空目录 |
| 权限不足／空间不足 | 哪个操作和路径失败、原因、已完成与未完成数量 |
| 文件变化／并发冲突 | 文件状态已变化，阻止过时写入；提供刷新、重试或另存路径 |
| Agent 审批 | 文件范围、源与目标、改动理由、不可恢复标记、批准状态 |
| 阅读器失败 | 已尝试的格式支持与失败原因；保留下载、详情和返回目录能力 |
| 无障碍操作 | 可见焦点、语义标签、键盘完成导航／对话框／选择；颜色不作为唯一状态信号 |

桌面文件列表支持方向键移动焦点、Enter 打开、Space 选择，Escape 关闭弹层；具体快捷键有界面提示且可由触屏／鼠标替代。对话框打开时焦点进入对话框，关闭后返回触发控件。图标按钮必须有中文可访问名称和提示，图标颜色不能独自表达风险或状态。加载、空目录、卷不可用、权限／空间不足、部分成功、冲突和阅读器失败状态均显示原因及下一步操作。

## 图标与组件基线

可直接查看 [图标规范与样例页](icon-study.html)：包含 26 个固定提交的 Lucide SVG、名称搜索、类别筛选和尺寸调整。Lucide 是已确定的图标库；图标页的暗色展示仅用于研究样式，不属于产品暗色主题承诺。

| 候选 | 适用证据 | 代价／待核验 | 建议 |
| --- | --- | --- | --- |
| Lucide | 线性图形风格适合文件操作密集界面；本地已保存 README、许可证和官方指南 | 使用 `lucide-react`，按需导入；升级依赖时检查图标变更 | **采用**，统一描边粗细和尺寸，不混用多套图标 |
| Tabler Icons | 图标覆盖广，官方许可页面说明图标为 MIT；本地有固定提交和许可文本 | 部分图标细节密度高；需统一尺寸与描边，不与 Lucide 混用 | 次选；若原型中文件类型图标覆盖更好再替换 |
| Phosphor | 多种视觉粗细可区分导航与强调状态，本地已有仓库 README 和许可证 | 风格层级容易造成图标表达不一致；确认具体框架包和许可后再用 | 备选，不建议首期使用多重量体系 |

图标库用于导航、动作和状态；文件类型使用一组有限且语义清楚的映射，未知类型使用通用文件图标。危险动作使用文字标签（如“永久删除”），不能只靠垃圾桶图标。

前端定为 React + TypeScript + Vite。组件策略采用少量 Radix Primitives 管理对话框、菜单和焦点／键盘行为，配合 FileSage 自有样式与业务组件；不用完整后台模板。复杂表格、审批卡、上传队列和阅读器工具条按产品语义设计。图标使用 `lucide-react` 按需导入。

设计令牌：间距按 4 px 递增，卡片圆角 8 px，主要操作高度 40 px（手机触控区至少 44 px），正文 14–16 px、辅助信息不低于 12 px；强调色为松绿，危险色仅用于删除／冲突等状态。CSS 变量集中维护颜色、间距、圆角与阴影，避免组件自行定义色值。

## 调研依据与证据边界

真实产品参考集中在文件管理、照片和文档管理：Nextcloud Files、File Browser、Filestash、Copyparty、Immich、PhotoPrism、PiGallery2、Paperless-ngx 和 Stirling-PDF。它们分别覆盖目录导航、批量管理、照片时间线、文档元数据过滤和预览工作流；这些是产品类别匹配与公开文档／代码结构观察，不表示已在本地部署做可用性测试。对 Paperless-ngx 和 Nextcloud 的公开截图只取得了搜索结果描述，未直接核验像素级视觉细节，因此本稿不把具体视觉细节作为设计证据。

新增前端参考为 8 个 GitHub 仓库；[前端与图标仓库索引](../../reference/catalog.md)链接至固定提交和上游资料。公开仓库只保留研究结论、来源及哈希清单，不分发上游原文；官方页面来源见 [reference/official](../../reference/official/manifest.json)。资料检索与本地完整性验证方法见 [reference README](../../reference/README.md)。组件候选的官方材料包括 [Radix 无障碍说明](https://www.radix-ui.com/primitives/docs/overview/accessibility)、[Radix 组件介绍](https://www.radix-ui.com/primitives/docs/overview/introduction)、[Tabler 许可](https://tabler.io/license)、[Lucide 指南](https://lucide.dev/guide/)、[Phosphor](https://phosphoricons.com/)、[shadcn/ui 文档](https://ui.shadcn.com/docs)和 [PrimeVue](https://primevue.org/)。

来源是设计取舍的线索，不是对当前版本、长期维护、安全性、可访问性或 FileSage 性能的背书。正式实现后仍需检查键盘、触屏、长目录、窄屏、依赖体积和许可证，并在真实手机浏览器验收。

## 交付与边界

[React 交互原型](prototype/README.md)覆盖文件、照片、Agent 审批和任务页面，并提供手机视图切换，用于检查布局与关键状态。原型中的上传、文件操作和审批只演示前端状态，不会访问或修改真实文件。生产页面已覆盖主要信息架构；未通过真实浏览器或服务器验证的功能继续按实施路线标注。

目录优先、通用文件默认列表、照片默认网格、浅色主题、四项手机底栏、React + TypeScript + Vite、Radix 基础交互组件和 Lucide 图标构成本次设计基线。文件、上传、任务、Agent 与主要阅读流程已有实现；具体格式、操作和部署验收状态见 [PRD](../PRD.md)、[TECH](../TECH.md) 与[实施路线](../IMPLEMENTATION_PLAN.md)。窄屏浏览器视口已检查，真实手机触控验收仍由用户完成。
